## Data contract (the tidy schema everything downstream uses)
`loader.load_activities(path) -> pd.DataFrame` returns one row per run with at least:
- `activity_id` (int), `date` (datetime64, tz-naive local), `name` (str)
- `distance_km` (float), `moving_time_s` (int), `elapsed_time_s` (int)
- `pace_min_per_km` (float, moving_time based), `avg_hr` (float, nullable)
- `elevation_gain_m` (float, nullable)

Rules:
- Filter to runs only (`Activity Type == "Run"` when reading real Strava CSVs).
- Convert units defensively: Strava exports mix meters/seconds and pre-formatted strings across versions, so coerce numerics with `pd.to_numeric(errors="coerce")` and derive `distance_km`/times from whatever numeric columns are present.
- Drop rows with `distance_km <= 0` or `moving_time_s <= 0`. Log how many rows were dropped.
- The synthetic generator must emit a CSV whose columns the loader can read through the same code path (so the loader is exercised by the sample data, not bypassed).

## Synthetic data generator (`generate_sample.py`)
Produce ~16 months of realistic run data (roughly 4 runs/week with rest weeks) so the dashboard looks alive on first launch:
- A gradual fitness trend: average pace improves slowly over time with week-to-week noise.
- A mix of run types by distance (easy 5–8 km, tempo ~10 km, long runs 16–25 km, occasional short 3 km).
- Heart rate correlated with pace (faster ⇒ higher HR) plus noise; leave ~10% of `avg_hr` missing to prove the code handles nulls.
- A couple of multi-week gaps to make the Fitness/Freshness curve interesting.
- Seed the RNG so output is reproducible. Write to `data/sample/activities.csv`.

## MVP features (build all of these)

### 1. Fitness & Freshness (the headline feature)
Recreate Strava Premium's Fitness/Freshness chart from first principles.
- Define a transparent **daily training load** per run. Use a duration × intensity model:
  `load = moving_time_min * intensity_factor`, where `intensity_factor` is pace relative to an estimated threshold pace (faster relative pace ⇒ higher factor). If `avg_hr` is present for a run, optionally blend an HR-based TRIMP term. Document the exact formula in `training_load.py` docstrings and the README.
- Aggregate to a daily load series (days with no run = 0).
- **CTL (Fitness)** = exponentially weighted moving average of daily load, 42-day time constant.
- **ATL (Fatigue)** = EWMA, 7-day time constant.
- **TSB (Form)** = CTL − ATL, shifted one day.
- Expose `compute_fitness_freshness(daily_load) -> DataFrame[date, ctl, atl, tsb]`.

### 2. Best efforts & race prediction
- Best-effort pace at the activity level for standard distances (fastest run of ≥3 km, ≥5 km, ≥10 km, ≥half, etc.), i.e. the fastest average pace achieved over a run of at least that distance.
- A **pace-vs-distance curve** (log-x scatter of every run: distance vs pace) with the best-effort frontier highlighted.
- **Riegel race predictions**: from the best recent effort, predict finishing times at 5K/10K/half/marathon using `T2 = T1 * (D2/D1)^1.06`. Return a small table `predict_races(best_effort) -> DataFrame[distance, predicted_time]`.

### 3. Personal records
- All-time PRs for 5K/10K/etc. based on best-effort logic above.
- A "recent form vs all-time best" comparison so the user can see if they're currently near a PR.

### 4. Consistency & load management
- Weekly and monthly distance totals (bar charts).
- Current and longest run streak (consecutive weeks with ≥1 run).
- **ACWR** (acute:chronic workload ratio = 7-day load ÷ 28-day load), with the commonly cited 0.8–1.3 "sweet spot" band shaded on the chart. This is a real sports-science metric and a nice statistical touch.

### 5. Trends
- Rolling 30-day average pace over time (is the runner getting faster?).
- Average HR over time where available.

## The dashboard (`app.py`, streamlit)
A clean multi-section single page (use `st.tabs` or an `st.sidebar` radio):
- **Overview**: headline KPIs (total distance, total runs, current Fitness/Form, current ACWR status) as `st.metric` cards.
- **Fitness & Freshness**: the CTL/ATL/TSB chart with a short plain-English caption explaining what "Form" means.
- **Performance**: pace-vs-distance curve + PR table + Riegel race-prediction table.
- **Consistency**: weekly/monthly volume + ACWR chart.
- A sidebar control to switch between the bundled **sample data** and a **real export** the user placed in `data/raw/`.
- On first run with no real data, default to sample data so the app is never empty.
- Every chart gets a one-sentence caption a non-runner could understand.

## Tests (pytest — write real assertions, not placeholders)
- `test_training_load.py`: EWMA with a constant load converges to that load; TSB = CTL − ATL; a spike in load raises ATL faster than CTL.
- `test_performance.py`: Riegel predicts a longer time for a longer distance and matches a hand-computed value within tolerance; best-effort selection returns the fastest qualifying run.
- `test_loader.py`: the synthetic CSV loads without error, has the contract columns and dtypes, and rows with zero/negative distance are dropped.
